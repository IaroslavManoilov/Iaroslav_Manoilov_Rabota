# Первая настройка на Mac

## Установка и открытие

Нужны Git, Python 3.11+, Google Chrome, VS Code с Codex или Codex app. Использовать новый аккаунт ChatGPT. Установку приложений при необходимости выполнить обычным способом; пакет не устанавливает системные приложения и не меняет настройки аккаунта.

Клонировать репозиторий по README.md, открыть корень и отправить START-HERE.md. Установить локальные зависимости:

```sh
bash scripts/bootstrap-macos.sh
bash scripts/open-admin-macos.sh
```

Playwright подключается к установленному Chrome через CDP; отдельный скачанный Chromium для этой утилиты не нужен. В browser-плагинах конкретного Codex может быть другой механизм подключения: использовать реально доступный, не утверждать, что текущие инструменты Windows автоматически появились на Mac.

## Входы

В отдельном Chrome вручную войти в `https://admin.vitra.md`. Если админка требует дополнительную проверку, пользователь проходит её сам. Войти в новый аккаунт ChatGPT; создать проект `Content`, добавить туда действующие инструкции карточек и OVERRIDES. Можно назвать проект иначе, записав его фактический URL в `config/workspace.local.json` → `content_project_url`. Один чистый чат на standalone SKU или одну подтверждённую семью; не переиспользовать чат другой модели.

Пример конфига не содержит паролей. Cookie остаются в игнорируемом локальном Chrome profile, access token используется только в памяти browser-контекста. Не переносить Windows DPAPI credentials и не копировать чужие cookie. Старые ChatGPT Project IDs не использовать.

Если браузерный инструмент недоступен, чтение можно проверить встроенной утилитой:

```sh
.venv/bin/python styles/work/cms_read.py --health
.venv/bin/python styles/work/cms_read.py --sku 'ТОЧНЫЙ_КОД'
```

`--health` делает обновление авторизованной сессии и GET справочников, без изменения товаров. `--sku` ищет точное совпадение, раскрывает возможные parent, сохраняет локальный снимок и всю обнаруженную семью. Инструмент не содержит команд создания, обновления или удаления.

## Когда настройка закончена

Codex сохраняет `styles/work/reports/environment-check.md`:

- фактический корень, ОС и версии Python/утилит;
- чтение CMS и доступ к справочникам (проверено или ошибка без секретов);
- точное разрешение SKU/ID и чтение семьи, если предоставлен код;
- наличие браузерного средства для взаимодействия с UI;
- URL нового Content project и возможность нового чата, без личных переписок;
- способ записи: поддерживаемый UI либо отдельно проверенный адаптер; если не проверен — так и указать;
- отсутствующие доступы и конкретные следующие действия.

Не выполнять тестовые изменения случайной карточки ради проверки доступа. Проверку записи совместить с первым явно разрешённым рабочим заданием, обязательно со снимком до записи и fresh GET после. Для создания установить фактический контракт/UI: один только успешный GET не доказывает возможность создания.

## Перенос в другую папку

Закрыть отдельный Chrome, переместить весь проект, открыть новый корень, пересоздать venv, запустить браузер из нового корня. Код вычисляет root от своего файла. Не менять исходники ради имени пользователя. Профили/локальные отчёты переносить приватно, не через публичный GitHub.

## Возможные проблемы

- `CDP unavailable`: отдельный Chrome не запущен, порт изменён или занят; проверить локальный endpoint, не завершать чужие процессы автоматически.
- `Admin tab missing`: открыть админку именно в отдельном профиле.
- `auth 401/403`: вручную войти в CMS, затем повторить чтение. Не печатать auth-ответ.
- `SKU not found`: проверить полный код и результаты/пагинацию; это не разрешение создавать новый товар.
- Другой аккаунт не видит Content: создать проект на нём; репозиторий не переносит право доступа старого аккаунта.
