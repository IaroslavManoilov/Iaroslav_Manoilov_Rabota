# ViTRA — постоянные инструкции Codex

Общайся на русском. Этот репозиторий — переносимый рабочий проект товарного каталога vitra.md. Пользователь работает на macOS в Codex и VS Code с нового аккаунта. Не предполагай наличие старых чатов, подключений или входов Windows.

## Начало сессии

Прочитай README.md, instructions/OVERRIDES.md и регламент нужного трека. При первом запуске выполни docs/MAC-SETUP.md. Корень проекта определяется расположением этого AGENTS.md, а не именем пользователя или абсолютным путём. Рабочие материалы — styles/work. Используй относительные пути. При переносе папки сохрани её структуру; не возвращайся к прежней папке Windows.

Приоритет: прямые актуальные инструкции пользователя → instructions/OVERRIDES.md → instructions/vitra-product-cards.txt и instructions/vitra-product-photo.txt → docs → исторический код. В двух исходных регламентах есть различия по медиа; для отдельного фото-трека приоритет имеет photo-регламент. Исторические скрипты и README не отменяют поздних уточнений.

## Режим работы

После настройки пользователь отправляет SKU/ссылку и задачу. Выполняй исследование, подготовку, разрешённое сохранение и свежую проверку. Не заканчивай одним планом или текстом, когда пользователь просит выполнить работу в админке. Обычные обратимые шаги выполняй без повторных вопросов. Отсутствующий доступ, неизвестную модель или неясное объединение не подменяй предположением.

Карточки: instructions/vitra-product-cards.txt, docs/PRODUCT-WORKFLOW.md.
Простые товары: docs/SIMPLE-PRODUCT.md.
Parent и варианты: docs/PARENT-VARIANTS.md.
Фото: instructions/vitra-product-photo.txt, только отдельный разрешённый трек.
CMS/API: docs/CMS-ADAPTER.md. Сначала докажи работоспособность чтением.

Уточняй создание/объединение, если дан только код и намерение неоднозначно. Явное «создай» разрешает создание соответствующей карточки; явное «обнови» не разрешает создавать дубликаты. Для одного кода сначала найди точное совпадение, включая варианты в parent. Если совпадений несколько — останови запись до разрешения неоднозначности. Не заменяй SKU по частичному совпадению.

## Границы сохранения

Не менять цены, остатки, статус, публикацию, поставщика и бренд без отдельного поручения. Проверка бренда в исследовании не разрешает менять связь бренда в CMS.

Медиа нельзя изменять, удалять, добавлять, восстанавливать, пересохранять, переставлять или переназначать при работе с карточкой. Требуется отдельное прямое разрешение в текущем запросе. Если сохранение автоматически затрагивает медиа — найди поддерживаемый способ без изменения медиа; иначе не сохраняй и сообщи проблему. Это относится и к преобразованию простых товаров в варианты.

До записи сохрани локальный снимок затрагиваемых карточек и связей. Перед каждым сохранением проверь diff и актуальность исходного состояния. Не отправляй полный старый JSON карточки вслепую. После записи читай каждую карточку по ID заново и сравнивай разрешённые и защищённые поля. При частичном сбое семьи сохраняй точный checkpoint; не повторяй создание уже созданных сущностей.

## Контент и источники

Идентичность и факты проверять по реально открытым источникам. RU → RO → EN. Не выдумывать функции, материал, сертификаты или страну. Названия и преимущества без бренда и артикула; проверенные бренд/модель допустимы в SEO. Все применимые характеристики, точная существующая подкатегория, программный подсчёт SEO. Подробные требования — в регламенте.

Варианты одной подтверждённой серии объединять в один parent. Общие признаки — общие; реально отличающиеся — вариабельные. Не присваивать всем вариантам размеры/вес одного из них. Parent не является дополнительным физическим SKU.

Все значения опций характеристик начинаются со строчной буквы на всех языках. Исключения — официальные модели, SKU, аббревиатуры, коды и обозначения GN, UV, IPX5 и т. п. Проверять и parent, и каждый variant после сохранения. Системную нередактируемую опцию исправлять поддерживаемым интерфейсом либо оставлять задачу needs_review.

## Проверка и состояние

Держи отдельный чистый чат ChatGPT Project Content на один SKU или одну подтверждённую семью. На новом аккаунте пользователь создаёт свой проект; URL задаётся локально. Не использовать ID старого проекта. Не удалять чаты, аккаунты или сессии по собственной инициативе.

Очередь: styles/work/batch_state/batch.jsonl. Исследования и снимки: styles/work/product_runs/<UTC>_<SKU>/. Статусы: pending, in_progress, needs_review, failed, completed_verified. Историческое completed не является доказательством. После перерыва сначала перечитай состояние CMS.

Готово означает: проверены источники, заполнены требуемые поля, выполнены разрешённые изменения, свежим чтением проверены все затронутые ID; изображения проверены, только если заказан фото-трек. Сохрани final-verification.md и receipt по templates/receipt.example.json в retention/receipts, без секретов. В финале укажи SKU, parent/variants, ID/ссылки, что сохранено и проверено, ограничения. Частичную работу не объявляй полной.

## Данные и очистка

Не коммитить токены, cookie, пароли, .env, профили браузера, снимки CMS и рабочие отчёты. .gitignore — дополнительная защита, перед push проверять staged diff. Не выводить auth-ответы или значения секретов.

После каждых трёх новых полностью проверенных workflows допустима локальная очистка старых завершённых материалов, сохраняя последние три. Семья считается одним workflow. Только по receipt с точными путями и свежей сверкой очереди; pending/failed/needs_review/in_progress и непроверенное сохранять. Не удалять общие файлы, symlink/junction, пути вне проекта, исходники, настройки, credentials, profiles, supplier master inputs, очередь, receipts и итоговые проверки. Вести журнал путей/байтов/ошибок. Никакой фоновой очистки. Старые материалы Windows не становятся автоматически подходящими для удаления.

## Программирование инструментов

Изменяй только относящийся к задаче код, сохраняй изменения пользователя. Не считай новый Mac-адаптер проверенным на реальной CMS до чтения/записи и свежей сверки на разрешённом товаре. Если MCP graph подключён — сначала подтвердить проект/поколение, затем graph discovery и coverage для используемых путей; при отсутствии инструмента честно использовать исходники. Не требовать установки графа для самой обработки товара.
